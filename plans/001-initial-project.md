# 001 — kontoauszugs-helfer: initial project

Status: in progress
Owner: Needle Tools GmbH
Created: 2026-06-27

## Goal

A free, open-source, **100 % local** web tool that reconciles a Sparkasse
**Kontoauszug** / **Kreditkartenabrechnung** against a folder of invoices
(Rechnungen) and shows **which charges are missing a Beleg**. Forked and
generalized from the personal `abrechnungen` tool. Target users: German
Freelancer / Kleinunternehmer, small GmbHs, Vereins-Schatzmeister.

## Product decisions

- **Bank scope:** Sparkasse only for now. Architecture is pluggable so other
  banks can be added later without touching the engine.
- **Headline feature:** the Missing-Beleg report (matched / missing / unmatched
  + per-vendor download links + CSV export). Auto-rename is secondary.
- **Privacy:** no upload, no backend; optional local AI (Ollama) only; analytics
  usage-only and off by default; OSS so the logic is auditable.
- **Design:** Needle brand system (calm, trustworthy, light, green accent).
  Signature element = the Beleg-completeness meter as the hero.

## Architecture

Monorepo (npm workspaces, `packages/`):

- `@kah/core` — pure, isomorphic engine: `canon`, deterministic invoice field
  extraction, charge↔invoice matching (single / split / threshold), missing
  inference. No bank-format or DOM knowledge. Aliases extendable at runtime.
- `@kah/parsers` — pluggable `BankParser` registry. `sparkasse` is the only
  registered parser. `parseBankStatement()` is registry-driven.
- `@kah/analytics` — Rybbit wrapper. Sensitive data blocked at the API: fixed
  event enum + whitelisted non-sensitive props only. No-op without a site id.
- `@kah/web` — Svelte 5 + Vite app on the Needle brand system (local brand.css,
  fonts, logos). Currently: landing + Missing-Beleg report shell (mock data).
- `providers.json` (repo root) — community-editable vendor aliases + invoice
  links. Personal account IDs stripped to generic billing pages.

## Findings — demo statement PDFs

- The first-pass demo PDFs are plain monospaced text — they parse but do **not
  look like a real Sparkasse statement**. Goal: look real, data cleaned, still
  parses on re-upload.
- **The originals cannot be edited in place.** The Saalesparkasse PDFs render
  text via **subset fonts with scrambled glyph codes** (e.g. "Kontoauszug" is
  stored as `( Y A @ B `)Tj` glyph indices, not letters), so literal
  find-and-replace finds nothing, and white-box overlays would leave the real
  text extractable underneath — not real redaction.
- **Decision:** rebuild a faithful replica from the original's exact text
  geometry. We already extracted every text item's `x / y / font-size` for both
  statements (page 1). Re-draw those positions with fabricated/sanitized tokens
  + a few ruled lines, in a standard font. Looks like the original, contains no
  original content stream (truly clean), and we control the lines so it parses.
- Tooling available: `pikepdf` (installed) for inspection; `pdf-lib` for
  generation. To parse a Sparkasse PDF, reconstruct lines by grouping pdfjs text
  items by y-coordinate (plain `unpdf` text-merge collapses lines).

- [x] Rebuilt the demo PDFs as faithful Saalesparkasse replicas from the

      USD/EURO-Kurs sublines, totals, footer). Data fully fabricated; verified
      to look real (rendered via PyMuPDF) and to parse (konto 7 / visa 8).
